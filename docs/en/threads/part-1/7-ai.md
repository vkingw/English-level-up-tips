# Learning English with AI: From Practice to Real Delivery

AI can reduce the time required to find material, create exercises, and receive first-pass feedback. It cannot perform your retrieval, listening discrimination, articulatory movement, judgment, or real communication. This chapter answers one question: **how can AI enter English practice without becoming a substitute for English ability?**

> Verified **2026-08-24**. Product features change by region, age, language, device, account, and plan; check the official help page before use. The training method below is not tied to one provider.

## Define “Can Use English”

Do not begin with hours or word counts. Write one real task first:

```text
Scenario: I need to introduce an AI project in an English online meeting.
Audience: Three overseas colleagues who do not know the technical details.
Definition of done: Explain the problem, proposal, risks, and next action in three minutes; handle two follow-up questions; send a follow-up email under 150 words.
Deadline: 2026-09-30.
Evidence: Recording, transcript, question log, email draft, and revision.
```

A useful goal contains a situation, audience, action, acceptance criteria, deadline, and evidence location. AI can help you practise and check; it cannot define completion for you.

## 1. Save a Baseline Before AI Enters

Do not ask AI to edit, translate, or hint on the first attempt. Complete four 10–15 minute tasks on one topic:

1. **Listening**: hear a two-to-four-minute authentic clip and write the gist, three details, and one uncertainty;
2. **Reading**: read one page and write a five-sentence summary plus one counterexample;
3. **Speaking**: speak for two uninterrupted minutes and save the raw recording;
4. **Writing**: write a 120–180-word work email without a dictionary or AI rewrite.

Score each dimension from 0 to 2. This is not an exam score; it is a repeatable snapshot:

| Dimension | 0 | 1 | 2 |
| --- | --- | --- | --- |
| Task completion | Core action missing | Partly complete | Real purpose met |
| Comprehensibility | Hard to follow | Repeated clarification needed | Mostly understood once |
| Accuracy and range | Errors block meaning | Basic meaning gets through | Forms and chunks are stable enough |
| Organisation and fluency | Fragments only | A thread with many pauses | Clear structure and forward movement |
| Revision and transfer | Feedback cannot be used | Local corrections possible | Can use the change in a new context |

Record samples, scoring reasons, and error evidence in the [English Diagnostic](../../templates/english-diagnostic.md). Without a baseline, you cannot tell whether AI improved ability or merely polished a product.

## 2. Choose a Workspace Without Confusing Functions

### Guided learning: one instructional conversation

Use it for scaffolded explanation, questions, hints, open tasks, quizzes, and knowledge checks. Ask AI to let you answer first and provide the smallest useful hint. Do not treat each answer as an authoritative lesson.

### Projects: long-running context and artefacts

Use them for goals, permitted material, chat history, errors, and work. The ChatGPT Projects help page says projects keep chats, files, instructions, and project context together. **The same page explicitly says Study Mode does not apply to Project conversations.** Do not assume placing one inside the other combines both capabilities.

A more portable combination is:

1. maintain [Learning State](../../templates/learning-state.md) locally;
2. keep only permitted material and work in a project;
3. open a separate guided-learning conversation when needed;
4. write evidence, errors, and the next action back to the local file after every session.

Platform memory is a convenience layer, not a source of truth. Your learning should survive a device, account, or model change.

## 3. Use One Task Card Every Time

```markdown
# English Task Card

Date: YYYY-MM-DD
Real situation:
Action: understand / read / say / write / ask / revise
Acceptance criteria:
Material and source:
Unaided baseline location:
AI may: prompt / question / correct / generate parallel tasks
AI may not: answer for me / rewrite a whole section / invent a source
Output location:
Feedback evidence:
Recurring error:
Smallest next task:
```

Write what AI may not do before practice begins. At the end, select one to two high-impact issues rather than collecting fifteen suggestions.

## 4. Divide Tools by Task

| Task | Useful capability | Boundary to verify yourself |
| --- | --- | --- |
| Guided learning and checks | ChatGPT Study Mode; Gemini learning, quizzes, and flashcards | Does it let you answer first? Are explanations sourced? Is the feature available to your account? |
| Long-running context | ChatGPT Projects; Claude Projects | Project permissions, file retention, memory scope, and export |
| Learning from your sources | NotebookLM; file-enabled projects | Original page, rights, privacy, and whether the model stays within the material |
| Web research with citations | Perplexity or search-and-citation products | Open the primary page and check that it supports the claim |
| Explanation and feedback | ChatGPT, Claude, Gemini | Fluent answers can still be wrong; use criteria and external verification |
| Language polishing | DeepL Write or general models | Keep the draft and explain each change |
| Live speaking | Gemini Live, ChatGPT Voice, and similar features | Recognition is not natural pronunciation; availability changes |

This is not a ranking. Consider sensitivity, task, language, feedback quality, and exportability before selecting a tool.

## 5. Vocabulary: Move from Recognition to Use

### Select authentic chunks

Give AI material from your reading, meeting, or project instead of asking for random lists. Prioritise chunks that affect comprehension, recur in your work, and fit multiple sentences.

```text
Select eight chunks from this authentic material that most affect comprehension and are most likely to recur in my work.
Explain the selection first. For each chunk provide the current sense, pronunciation cue, common collocation, source sentence, a gap, and a work-context rewrite.
Do not show the answers. Let me complete the gaps, then review form, meaning, collocation, and context.
Flag anything that needs dictionary or corpus verification.
```

### Four encounters instead of one bookmark

| Time | Action | Evidence |
| --- | --- | --- |
| Day 0 | Recall meaning from the source and read the sentence aloud | Recall accuracy and recording |
| Day 1 | Complete a gap and make one personal sentence | Can the chunk be produced? |
| Day 3 | Choose the correct collocation in a new topic | Transfer to a new context |
| Day 7 | Use it in a 60-second talk or short paragraph | Can it be retrieved under pressure? |

AI can create parallel tasks, but keep `source sentence → your answer → answer key → error cause`. Use delayed retrieval from the [Vocabulary chapter](2-vocabulary.md) before deciding whether to increase spacing or reduce difficulty.

## 6. Listening: Turn “I Missed It” into a Diagnosis

### Five kinds of listening error

1. **Unknown language**: the word or structure is not known;
2. **Known but not heard**: the written form is known but the sound connection is weak;
3. **Connected speech, reduction, or stress**: boundaries and rhythm changed;
4. **Attention**: length, task load, or a missed transition caused the failure;
5. **Background knowledge**: the words were heard but the topic was not understood.

On the first listen, do not look at the transcript. Record the gist, three details, and one uncertainty. On the second pass, mark time ranges and ask AI to work only on those segments:

```text
Here is my first-listen record and the time ranges I missed. Do not provide a complete transcript first.
Classify each range as unknown language, known-but-not-heard, connected speech/reduction, attention, or background knowledge, and explain the evidence.
Let me guess the sentence before showing an official or reliably checked transcript.
Then create slow chunks, natural-speed practice, one dictation gap, and an untimed retelling for the two segments that affect comprehension most.
```

Shadowing is not the finish line. The acceptance test is a retelling with the transcript closed and a similar clip one week later. Compare important material with official captions or human review; an AI transcript is not automatically the original.

## 7. Speaking and Pronunciation: Measure Communication

### A 12-minute session

1. One minute: describe the situation and goal without notes;
2. Six turns: speak one or two sentences per turn while AI asks or clarifies;
3. Two minutes: complete the same task continuously and save the recording;
4. Three minutes: replay it and mark pauses, repetition, chunks, and one high-impact pronunciation feature.

```text
Run a six-turn [scenario] conversation. Speak only one or two sentences per turn and wait.
Do not complete my sentence unless I ask. At the end, review task completion, comprehensibility, interaction, pauses, chunks, and one high-impact pronunciation feature.
Quote transcript evidence. If speech recognition is insufficient for a pronunciation judgment, say that it is insufficient.
Give one minimal contrast and one parallel scenario that I must complete without you.
```

Keep the first recording, transcript, feedback, and second take. Successful recognition does not prove natural pronunciation, and failed recognition does not prove an error. Obtain permission before recording private meetings or another person's voice, and confirm storage and sharing boundaries.

## 8. Reading: Train an Evidence Chain, Not a Summary Collection

Read first, then ask AI to coach. Write the author's claim, key evidence, hidden assumption, key terms, and one counterexample. Use this protocol:

```text
Do not summarise first. Ask me for the author's claim, key evidence, implicit assumption, and one possible counterexample.
Follow up until I can point to the original location.
Finally create three columns: explicit support / reasonable inference / unsupported by the text.
Quote a paragraph or page for every judgment; write “evidence not found” when necessary.
```

For research reading, prefer papers, official documentation, contracts, data, and complete cases. Asking a model to reconstruct a paper from memory makes “I saw a summary” look like “I checked the source.”

## 9. Writing: Keep the Author's Hand

Keep an unaided draft, an annotated version, and a self-revised final. Write a brief before the prose: audience, purpose, conclusion, evidence, constraints, action request, and length.

```text
First judge whether this text serves [audience/purpose/action request].
Do not rewrite it wholesale. Rank no more than five issues by impact; quote each passage, explain the effect, and give a minimal example.
Separate facts/sources, structure/reasoning, and language/expression. Do not invent uncertain facts.
Ask me to rewrite the weakest paragraph, then review only the change in version two.
```

For a work email, ask AI to do three separate jobs:

1. **Comprehension check**: can the reader identify what, by when, and why;
2. **Risk check**: are there over-promises, ambiguity, unsupported facts, or an unsuitable tone;
3. **Compression check**: can background be reduced while the request and next action move forward?

If you cannot explain a change, it has not become your skill. The named author remains responsible for facts, positions, and authorship in important messages, proposals, and public writing.

## 10. Bring English Back into Real Work

AI practice can remain in a training room forever. Each month choose one real delivery that connects the skills:

| Real task | Input | Output | Review focus |
| --- | --- | --- | --- |
| AI project meeting | Product brief, agenda, risks | Three-minute introduction, question log, follow-up email | Did you understand decisions and objections? |
| Technical article talk | Original article, term list | Five-minute explanation and two answers | Can you explain in your own words? |
| Customer discovery | Interview questions, domain context | Clarification, confirmation, meeting notes | Did you confirm scope and commitments? |
| English issue or pull request | Code, failure log, acceptance criteria | Issue, fix note, test result | Can another person reproduce the problem? |
| Job or partnership conversation | Resume, project evidence, role description | Introduction, answers, follow-up note | Did you connect experience to their need? |

Judge a real task first by whether communication moved the work forward, not by whether every sentence sounded native. Preserve raw output, feedback, revision, and the next short drill.

## 11. Feedback Protocol and Retesting

Require evidence rather than general encouragement:

```text
Restate the task and acceptance criteria so I can correct misunderstandings.
Let me attempt it first. Separate feedback into task completion, comprehensibility, accuracy/range, organisation/fluency, and revision/transfer.
Select only one to three issues per category that most affect the result, quoting my words or a time range.
Mark facts as verified, reasonable inference, or unconfirmed. Do not invent sources.
Give one minimal hint, one parallel task, and a retest condition. Do not complete the final delivery.
```

Review completion, quality, retention, and transfer each week. Retest on day 30 and week 12 with the same topic, similar difficulty, and the same time limit. If polished outputs improve while unaided baselines do not, reduce assistance instead of adding tools.

## 12. Privacy, Copyright, and Account Boundaries

Do not upload unauthorised course material, company secrets, customer data, student records, children's data, private recordings, or third-party photographs. Removing names does not necessarily anonymise content. Prefer local processing or the smallest necessary excerpt for sensitive material.

Before sharing a project, inspect members, link permissions, files, project instructions, chat history, exports, and local caches. Use copyrighted material only within your rights and preserve source and licence records. You remain responsible for AI-generated sentences, translations, explanations, and published claims.

## 13. Seven Days, Thirty Days, Twelve Weeks

### Seven days: establish the loop

- create local state and one unaided baseline;
- complete the three most important tasks across vocabulary and the four skills;
- preserve `raw output → feedback → second version`;
- on day seven, ask whether AI created more output or merely more reading.

### Thirty days: build an error library

- create minimal contrasts, parallel tasks, and source links for recurring errors;
- complete at least one unaided task every week;
- remove unsupported, duplicated, or over-broad feedback;
- repeat baseline conditions and compare independent performance, not polished artefacts.

### Twelve weeks: complete a real delivery

- choose a real meeting, presentation, article, exam, or collaboration as the final task;
- gradually reduce hints, translation, and whole-section rewriting;
- conduct human fact, source, privacy, and language review;
- export state and work so training survives the product.

## Ten Questions Before You Call It Done

1. Can I explain the key conclusion without the chat?
2. Did I complete an unaided baseline first?
3. Have I used vocabulary actively in a new context?
4. Are listening errors classified rather than labelled only “missed”?
5. Did I save a recording, transcript, and second speaking take?
6. Can reading judgments return to a paragraph or page?
7. Can I explain and reproduce my writing changes?
8. Did a real audience receive, hear, or use the output?
9. Did I expose unnecessary data or third-party content?
10. Can I complete the next similar task with less assistance?
