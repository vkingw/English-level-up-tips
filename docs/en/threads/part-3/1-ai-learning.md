# Learning Anything with AI: From Chat to Verifiable Work

AI makes it easy to confuse a complete answer with personal learning. A real result survives after the answer is closed: you can explain, judge, perform, transfer, and leave work another person can inspect.

## The Seven-step Loop

1. **Define a real outcome**: exam, report, program, presentation, decision, or lesson.
2. **Save a baseline**: attempt it independently to expose prerequisites and errors.
3. **Select sources**: prefer primary documentation, textbooks, papers, data, and cases.
4. **Use guided practice**: ask for questions, hints, and layers rather than substitution.
5. **Produce actively**: close sources and explain, code, write, calculate, or demonstrate.
6. **Obtain plural feedback**: AI is one vote; tests, sources, experts, or users validate important judgments.
7. **Update state**: save evidence, errors, and the next action for another session.

## Tool-selection Order

1. Is the data sensitive and permitted to upload?
2. Does the task need sources, long material, voice, code execution, or collaboration?
3. Can output be exported, reproduced, and verified independently?
4. Is it available for the region, language, age, account, and plan?
5. What does it cost in money and attention?

See [Learning English with AI](../part-1/7-ai.md) for the boundary between guided learning and projects and for dated official product notes. The same principles apply to programming, writing, exams, and research.

## Cross-session State

Use [Learning State](../../templates/learning-state.md) instead of asking a model to remember you. At the end of every session save:

- completed work and evidence location;
- claims verified by source or test;
- errors that still recur;
- the smallest next task and acceptance criteria.

The file should make sense to any model, another person, or your future self. Platform memory is a convenience layer, not the only record.

## Apply by Domain

### Programming

- write acceptance tests, interfaces, or failing examples first;
- ask for assumptions and risks before minimal changes;
- run tests, static checks, and security review yourself;
- separate “runs” from “correct requirement, safe boundary, maintainable design”.

### Writing

- keep the draft and review audience, purpose, facts, and structure first;
- require quoted passages rather than wholesale rewriting;
- return facts to primary sources and inspect quotation context;
- the named author remains responsible for the final position.

### Exams and Certifications

- build a capability matrix from the official syllabus and samples;
- answer before hints and create parallel tasks from error causes;
- complete regular timed, unaided simulations;
- do not treat a model-predicted score as an assessment.

### Industry Research

- separate facts, inference, forecasts, and recommendations;
- record publication date, measurement definition, and primary link for numbers;
- seek counterexamples, interests, and missing data;
- use qualified professionals for high-stakes decisions.

### Work Delivery

- state audience, decision, deadline, and acceptance criteria;
- split research, draft, validation, review, and publication;
- use only tools and data allowed by the organisation;
- record human reviewers, tests, and changes.

## Feedback Protocol

```text
Restate the task and acceptance criteria, then let me attempt it. Separate feedback into facts/sources, task completion, structure/reasoning, skill errors, and expression detail. Quote evidence and choose only one to three issues that most affect the result. Mark uncertainty and do not invent sources. Give one minimal hint and one parallel task rather than completing the final deliverable.
```

## Prevent Skill Outsourcing

- complete one unaided baseline each week;
- explain important concepts without the answer;
- explain every critical decision in important work;
- test generated code, cite research from primary sources, and revise prose as the author;
- reduce assistance when performance collapses without it.

## Privacy, Security, and Copyright

Follow organisational policy and applicable law first. Do not upload secrets, unpublished data, customer/student records, health or identity data, unauthorised work, or third-party private information. Use the minimum necessary excerpt. When deleting, inspect projects, shared links, history, and local copies. AI can produce infringing, biased, or dangerous material; the publisher remains responsible.

## Seven Days, Thirty Days, Twelve Weeks

### Seven days: one micro-deliverable

- define the real outcome and acceptance criteria;
- save an unaided baseline;
- use the loop for a one-to-three-hour deliverable;
- record where AI helped, misled, and what remains without it.

### Thirty days: repeatable workflow

- complete four loops for a recurring task;
- build prompt, source, test, feedback, and state templates;
- compare time, quality, rework, and independent performance;
- remove tool steps that do not improve the result.

### Twelve weeks: real delivery

- choose a project with value in work, study, or life;
- obtain real-audience feedback every two to four weeks;
- complete fact, test, security, privacy, and copyright review;
- export material and state, then write a one-page retrospective.

## Acceptance Questions

1. Can I explain key conclusions without the chat?
2. Can facts, numbers, and citations return to primary sources?
3. Has the output passed a real test or audience review?
4. What is inference and what remains uncertain?
5. Did I expose unnecessary data or third-party content?
6. Can I complete the next similar task with less assistance?
